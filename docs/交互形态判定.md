> `_lucy-recon\recon-keys\REPORT.md`（实测记录）、0.2.2.0–0.2.4.0 实机测试（Lead 提供）。

## 1. 结论（三选一）

- [ ] **A. 游戏已有完全键盘控制** → 补丁只做朗读
- [ ] **B. 有键盘但不完全** → 在游戏自己的输入/焦点层补全
- [x] **C. 没有键盘控制 / 没有控件模型** → 制造完全键盘控制

**结论**：**C 型**——原生键盘不覆盖界面（UI），游戏没有控件模型。
**判定人 / 日期**：keys-recon，2026-11-18（本机实测）；0.2.2.0–0.2.4.0 实装状态由 Lead 实机确认。
**证据**：
- `_lucy-recon\recon-keys\REPORT.md`：逐界面键盘响应实测
- `_lucy-recon\recon-keys\menu_model.json`：菜单项的矩形 / 点击模型
- `_lucy-recon\recon-keys\EMULATION.md`：拟态方案说明
- `_lucy-recon\shots-keys\`：实测截图

### 实测事实：哪些界面吃键盘

| 界面 | 键盘是否有反应 | 实测按键 |
|---|---|---|
| 标题菜单 | **完全无响应** | ↑ ↓ ← → / TAB / SPACE / ENTER / ESC / Z / BACK 均无反应 |
| 暂停菜单 | 完全无响应 | 同上 |
| 设置 | 完全无响应 | 同上 |
| 存读档 | 完全无响应 | 同上 |
| 特典 | 完全无响应 | 同上 |
| 历史（对话历史界面） | 完全无响应 | 同上 |
| 确认框 | 完全无响应 | 同上 |
| 剧情页 | **有反应** | ENTER=下一句；SPACE=显示/隐藏对话框；Z 或长按 CTRL=跳过；滚轮下=下一页；滚轮上=对话历史；ESC 或右键=暂停菜单 |

- 界面（菜单、设置、存读档等）只能靠鼠标点击：没有原生键位能移动选中项，
  也没有可以逐个遍历的控件模型。
- 唯一的键盘入口是剧情页。进出菜单、在菜单里选、确认，原来都必须用鼠标。

### 本作路线：拟态原生键盘，仍然没有导航模式

- C 型不等于「补丁自带一套导航模式」。本作采用**拟态原生键盘**：
  补丁把方向键 / Enter 翻译成鼠标 hover + click，模拟玩家用鼠标在界面上操作；
  **不新增任何模式开关，不在画面上新增可见元素**。
- 设计目标仍是**无导航模式**（符合用户要求）：玩家不需要进入/退出某种「补丁模式」，
  方向键就是操作界面，Enter 就是点击当前项。
- 诚实记录的代价：拟态点的位置来自画面矩形，不是游戏自己的控件模型；
  「补丁认为的当前项」和「画面高亮项」是否总是一致，必须逐界面实机核对
  （见第 5 节遗留缺陷）。
- **拟态点击的输入通道（0.2.3.0 实测）**：`Engine.dll` 的 USER32 导入表里没有
  `GetCursorPos` / `SetCursorPos` / `SendInput`——界面靠 `WM_MOUSEMOVE` 的 lParam
  定位置、靠 `GetAsyncKeyState` 轮询按钮，进程内注入硬件鼠标无效。补丁改为
  `PostMessage` 合成鼠标消息，并让按钮保持按下约 **2000ms**（实测按住不到 1 秒
  引擎不认、2000ms 才生效）。代价是**每次激活菜单项约 2.2 秒**才生效，
  这期间按键会被忽略——引擎行为，不是卡顿；点击由 tick 线程排队，不阻塞键盘钩子。

## 2. 「完全键盘控制」逐界面清点

A 类的判定条件是**全流程**纯键盘可完成，不是只测标题菜单。
本作是 C 型，下表记录「不装补丁时缺什么、补丁用什么补」。

| 界面 | 不装补丁能否纯键盘完成 | 游戏原生键位 / 焦点机制 | 缺什么 | 补法（A/B/C） | 游戏自身入口 |
|---|---|---|---|---|---|
| 标题菜单 | 否（键盘 0 响应） | 无；菜单项是绘制矩形，靠鼠标命中 | 全部键盘入口 | C：补丁拟态（方向键→合成鼠标移动，Enter→合成按下）；**0.2.4.0 已打通**（标题按钮用 `GetCursorPos` 判 hover，补丁在点击阶段同步移动真实光标） | 未从反编译确认（无控件模型） |
| 暂停菜单 | 否 | 无 | 全部键盘入口 | C：**已跑通** 8 项（帮助 / 跳过 / 历史 / 保存 / 读取 / 选项 / 标题 / 返回游戏），方向键 + Enter 实测 | 同上 |
| 设置 | 否 | 无；滑条 / 勾选靠鼠标 | 全部键盘入口 + 当前值朗读 | C：**已跑通**——5 条滑条 `←` `→` 调整、韩 / 日语言、全屏开 / 关；播报带画出的数值，读不到只播标签 | 同上 |
| 存读档 | 否 | 无；格子靠鼠标点 | 全部键盘入口 + 格子位置朗读 | C：**已跑通** 4×3 格 × 10 页，位置读作「第 N 页，第 r 行第 c 列，存档位 NN」（NN = 20×(页−1)+4×行+列）；读档实测、存档落盘未逐项实测 | 同上 |
| 特典 | 否 | 无 | 全部键盘入口 | C：拟态骨架已有，逐项覆盖未实测 | 同上 |
| 历史 | 否 | 无 | 全部键盘入口 | C：**只把滚轮放行给游戏；补丁不朗读历史**（0.2.4.0 仍如此） | 同上 |
| 确认框（退出 / 覆盖存档） | 否 | 无 | 全部键盘入口 | C：**已实装**——识别 `fmt=0x400` 多行绘制（最后一行以「？」结尾），自动朗读游戏原话，↑↓ 在「是 / 否」之间，Enter 确认，Esc=「否」；400ms 时效 + 3s 静默防重 | 同上 |
| 剧情页 | **是**（原生键盘可用） | 原生键位：ENTER / SPACE / Z / 长按 CTRL / 滚轮 / ESC / 右键 | 朗读 | 补丁只做朗读与重读，不改键位；同句去重（32 条 / 120s）、纯标点与打字机碎屑不读 | 不涉及 |
| 选项 | 否（原生键盘不覆盖） | 选项是 `fmt=0x100` 的点框文字（x 460..820、y 130..360，两条以上成对出现），无控件模型 | 选项朗读与键盘选择 | C：**已实装**——250ms 内识别、朗读「选项，共 N 项…」、↑↓ 选择、Enter 选中（只合成一次点击）、Esc 取消；首个选项屏（2 个分支条）实测选中成立、无确认框 | 未从反编译确认 |

补充事实：

- 游戏有没有**自己的**选中态 / 焦点链？——**没有**：界面没有控件模型，
  菜单项是绘制出来的矩形，点击靠坐标命中（实测结论）。
- 游戏有没有**自己的**键位表 / 输入映射？——剧情页有固定键位（见上表）；
  界面没有键位表，键盘完全不参与界面操作。
- 哪些键被游戏原生占用（补丁新增键必须避开）？——剧情页：ENTER、SPACE、
  Z、长按 CTRL、滚轮、ESC、右键。补丁新增键只用游戏没占用的键：
  `Backspace`、`Ctrl+Backspace`、`Alt+Shift+F9`。
- 界面打开 / 关闭是否由游戏自己的事件驱动（用于朗读触发）？——**否**；
  当前朗读依赖画面文本抓取，不是游戏事件（见第 3 节 X4、第 4 节第 6 条）。
  补丁靠画面内容判断界面（选项 `fmt=0x100`、确认框 `fmt=0x400`），
  并有**菜单屏幕跟随**：玩家用鼠标 / 读档 / 自动模式绕开补丁时，
  补丁依据画面剧情文字在 2.5 秒内把状态拉回剧情页（实测）。
- 操作语义是否与 `Framework/docs/操作逻辑公约.md` 对齐？——对齐：
  `Enter` 激活、`Esc` 返回、`Backspace` 重读、`Alt+Shift+F9` 切换语音后端；
  界面浏览用 `↑↓←→` 拟态（公约的「浏览上一项/下一项」语义）。
  差异与原因写在 [操作约定.md](操作约定.md)。

## 4. 验收（P4 填）

1. 不按任何补丁专属模式键，能否只用键盘走完本作主流程？
   **基本可以**：0.2.4.0 标题画面（`↑` `↓` + `Enter` 开始）、剧情页、暂停菜单、设置、
   存读档、选项、确认框都能用键盘；但**完整通关未验证**（存档落盘未逐项实测、
   历史不朗读）。
2. 键盘的「当前项」是否就是游戏自己的选中项？
   **未实测**：选项 / 确认框按画面特征识别并朗读；拟态光标按矩形中心最近方向移动，
   与画面高亮是否一致需逐界面核对。
3. 关掉补丁，游戏键位与行为是否完全不变？
   **是（设计如此，卸载实测未做）**：补丁不修改游戏文件；
   删除代理 DLL 并还原备份后即回到原版；存档与设置由游戏自己写，卸载不清除。
4. 补丁有没有新增画面上看得见的东西？
   **没有**（未发现新增可见元素；完整核对未实测）。
5. 补丁有没有让玩家背一套游戏里不存在的操作？
   **没有**：方向键 / Enter 对应界面操作，`Backspace` 重读，都是玩家已知语义；
   新增键都避开了游戏原生占用的键。
6. 朗读是否由游戏事件触发（而不是补丁扫描推断）？
   **否 / 部分**：当前朗读依赖画面文本抓取（见第 3 节 X4）；
   这是重复、漏句风险的主要来源，已按「整页追加只读新增部分」缓解。
7. 以上任一为「否」时，是否已在本文件第 5 节登记？**是。**

**证据**：keys-recon 2026-11-18 本机实测；0.2.2.0–0.2.4.0 实装状态由 Lead 实机确认；
截图与 JSON 在 `_lucy-recon\`（研究目录，不入库）。

## 5. 遗留缺陷（必须如实，没有就写「无」）

0.2.3.0–0.2.4.0 已解决：**暂停菜单、设置页、存读档页、确认框、首个选项屏的键盘操作**，
以及一批朗读噪音（同句重复、纯标点行、打字机碎屑、确认框反复触发、存档误报）；
0.2.4.0 另补**配音判据实机初步验证**（深档 48 句中 3 句判配音静默）。
以下是仍未解决的项。

| 界面/操作 | 缺什么 | 为什么本版补不上 | 玩家会感知到什么 | 计划 |
|---|---|---|---|---|
| 标题画面 | 逐项朗读覆盖 | 0.2.4.0 已能用键盘启动，但 4 项的朗读顺序 / 跳过按钮细节未逐项核对 | 可能读到不该读的项 | 逐项实机核对后补 |
| 历史界面 | 对话历史界面朗读 | 仍只把滚轮放行给游戏，补丁不朗读 | 翻历史后听不到内容 | 下一版实现朗读 |
| 存档流程 | 存档落盘 / 读回的逐项实测 + 存档摘要（时间、章节） | 界面已跑通，但没逐项验证 | 存档是否可靠未确认；只能听到位置，听不到摘要 | 逐项实测后补 |
| 所有拟态界面 | 「当前项 = 画面高亮」的一致性保证 | 无控件模型，只能按矩形近似 | 偶尔可能读的和画面选的不一样 | 实机逐界面核对，必要时调整方向判定 |
| 菜单激活延迟 | 引擎要求按钮保持按下约 2000ms | 引擎取输入的方式决定 | 每次激活等约 2.2 秒，期间按键被忽略 | 引擎行为，暂无更好办法 |
| 配音判据误差 | 启发式两类误判的实机核对 | 判据已初步验证，但同刻音乐 / 音效误判、语音延迟 >900ms 两类误差未逐条核对 | 个别句子该读没读（`Backspace` 可听）或该静默却读出来 | 收集样本后收紧判据 |
| 键位冲突 | 后端切换 / 重读键与游戏原生键是否冲突 | 未测 | 个别键可能被游戏先吃掉 | 实机测试 |
| 画面说明页（图片） | 图片内容朗读 | 游戏自带说明页是图片，无法朗读 | 完全听不到这部分内容 | 替代方案未实测 |
| 菜单滑条数值 | 播报格式定稿 | 已带画面数值，但格式（单位 / 百分比）未实测 | 可能听到标签 + 数值，但格式未定 | 实机确认后定稿 |
| 选项数字键直达 | 数字键直接选第 N 项 | 未实现（不计划） | 需用 ↑↓ 选择 | 不计划 |
| 其他语言 | 非简体中文版本的支持 | 只测过简体中文 | 其他语言版本未验证 | 有条件时测 |

> 允许带缺陷发布，但**不允许让玩家以为它被覆盖了**。
> 发布说明与测试问卷里要有一句与上表一致的话。
