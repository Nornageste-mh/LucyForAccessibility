# LucyForAccessibility

本仓库是**专门针对 Steam 游戏《露西 -她所期望的一切-》（Lucy -The Eternity She Wished For-，AppID 430960）** 的屏幕阅读器
辅助补丁 —— 一个游戏进程内的 **`d3dx9_40.dll` 代理 DLL**，
文字从游戏自己的 `ID3DXFont::DrawTextW` 出口取走，直接交给读屏 DLL（NVDA Controller Client / 争渡读屏 ZDSR / Windows SAPI），
界面用键盘操作，激活时用合成输入（鼠标消息 + 真实光标 + 按钮保持）点中游戏自己的按钮，没有模式键。

- 当前版本：**0.1.0.1**（见 `CHANGELOG.md`；这是**首个公开版本**，此前 `0.2.0.0`–`0.2.6.0`
  是同一份成果的内部迭代记录。本版把「完全键盘」做齐：标题、暂停菜单、设置、存读档、确认框、选项屏都能用
  方向键 / 回车 / Esc 操作；带配音的台词不自动朗读；切屏时序与状态错位做了修复）

## 说明

本补丁的作用：让使用读屏软件的玩家，也能基本正常地游玩《露西 -她所期望的一切-》。

**平台**：Windows x86。游戏是 32 位进程，所以补丁和 `nvdaControllerClient.dll` 都必须是 32 位。

- 游戏文本不是 Win32 控件，是引擎用 D3D9 自己画的像素 —— 对读屏软件来说整个窗口是一片空白。
  补丁替换游戏目录里的 `d3dx9_40.dll`（一个转发全部 336 个 D3DX 导出的代理 DLL），
  从 `ID3DXFont` 虚表的 `DrawTextW`（槽 15）实参里把**每一帧真正要画的文字**取走，
  所以**不需要读屏软件做任何特殊适配**，也不改游戏文件内容以外的任何东西。
- 朗读剧情：台词（游戏的剧情框里没有独立的"说话人"绘制，说到底是整句台词）。
  **有配音的台词不再叠一层 TTS**（人声已经在读了），但按 `Backspace` 仍能把这一句念出来。
- 朗读选项，并用 `↑`/`↓` + `Enter` 选择（用的是**游戏自己画出来的选项矩形**，不是猜的坐标）。
- 界面控件用 `↑`/`↓` 浏览、`Enter`/`Space` 激活、`Esc` 交还游戏；
  **没有模式键**，界面一出现就能操作。
- 游戏原生界面**只认鼠标**（标题、暂停菜单、设置、存读档、确认框、选项屏对键盘零响应），
  所以补丁用**合成输入**代替鼠标：向游戏窗口投递鼠标移动 / 按下 / 释放，同时把真实光标移到目标位置，
  并让按钮保持按下 2000 ms（实测短按会被引擎丢掉）—— 详见下面的「交互形态判定摘要」。
- 合成点击一次约 2.2 秒，所以界面操作会有"按了回车之后要等一下"的感觉，这是**实测出来的必需值**，
  不是懒。
- 剧情推进仍然用游戏自己的键（`Enter` 下一页、`Space` 显示 / 隐藏对话框、`Z` 跳过、
  按住 `Ctrl` 跳过）；补丁只补念当前句、不抢这些键。
- 语音后端按 `NVDA` → `争渡读屏（ZDSR）` → `SAPI` 逐级降级；
  按 `Alt+Shift+F9` 可以在**当前可用**的后端之间循环切换（下次启动保持），详见
  [语音后端与切换快捷键](#语音后端与切换快捷键)。

## 交互形态判定摘要（第 0 条纪律）

完整判定见 [`docs/交互形态判定.md`](docs/交互形态判定.md)（随仓库入库；判定口径是
「只看游戏自己读不读、写不写某个东西」，不是「补丁想不想用」）。

- **结论：C 型 —— 游戏没有界面控件模型，也没有任何原生键盘覆盖，补丁用合成输入制造键盘操作。**
  游戏里没有 Unity 那种「焦点 / Selectable / EventSystem」，也没有 KiriKiri 那种"枚举层、
  直接调层自己的点击处理"的入口：标题 / 暂停菜单 / 设置 / 存读档 / 确认框 / 选项屏
  逐键实测（292 张截图逐帧比对）对 `↑`/`↓`/`←`/`→`/`Tab`/`Enter`/`Space`/数字键的响应全是 0 像素变化，
  只有剧情页吃 `Enter`/`Space`/`Z`/`Ctrl`/滚轮/`Esc`。所以补丁只能**代玩家点鼠标**。
- **合成输入的三层**：①向游戏窗口 `PostMessage` 鼠标移动 / 按下 / 释放；
  ②用 `SetCursorPos` 把真实光标同步到目标（标题按钮是用 `GetCursorPos` 判断"指针在不在按钮上"的，
  只投消息不会生效）；③把假按键状态维持 2000 ms（引擎只认"按住够久"的点击）。
  补丁自己维护一个**朗读用的**选中项（不画 UI、不改游戏状态）。
- **无模式键**：界面一出现，`↑`/`↓` 就能浏览；没有旧的 `Tab` 导航模式。
- **屏幕识别**：补丁不截图、不做模板匹配，只靠"游戏画了什么字"判断当前是哪个界面
  （剧情框是 `fmt=0x410` 且框宽 990 或负数、选项是 `fmt=0x100` 的 1×1 点框且成对出现、
  模态框是一条含换行且末行以「？」结尾的 `fmt=0x400` 绘制、页码是 `1/10` 这类名牌）。
- **2026-11-19 实机冒烟**：标题按回车 15 秒内进正文；`Enter` 推进；`Backspace` 重读整页；
  `Ctrl+Backspace` 上一句；`Esc` 播报"暂停菜单"；暂停菜单 8 项逐项播报；
  设置页 5 条滑条 + 1 个开关，`←`/`→` 调滑条按轨道百分比点；存读档 4×3 格 ×10 页；
  确认框「保存进度吗？」识别并可用 `Esc` 点"否"；首个选项屏 `↑`/`↓` + `Enter` 选分支成功；
  `Alt+Shift+F9` 切换语音后端成功。
- **遗留缺陷清单**（与 `docs/交互形态判定.md` §5、`docs/project_status.md` §5 保持一致）：
  存档落盘 / 读回的自动化验证未闭环（点击已发出、游戏未弹确认框；手动可存档但"确实写了盘"无自动化证据）；
  历史（backlog）界面只放行滚轮、不朗读；滑条只播报离散档位；设置项当前值靠"读游戏画的数字"；
  完整通关未测；其他语言未测；合成点击每次约 2.2 秒（快不起来）。

## 安装（仅限正版玩家）

安装 = **替换游戏目录里的 `d3dx9_40.dll`** + 一个记录文件。
被替换的那个 DLL 由发布包里的安装脚本**在你自己的机器上、用你自己那份原档备份改名** ——
本补丁**不发布改好的游戏文件**，也不含任何游戏资源。

**为什么非得替换 `d3dx9_40.dll`**：本作引擎把 D3D9 扩展库当作普通依赖加载，
加载器优先找**游戏目录**里那份；补丁把自己做成同名代理 DLL，先把所有 336 个导出原样转发给改名后的原版
（`d3dx9_40_orig.dll`），再在 `D3DXCreateFontW` 与 `ID3DXFont` 虚表上挂钩子。
外挂的 `d3d9.dll` 代理、`hook` 注入器、`winmm.dll` 代理等方式我们都评估过：
D3D9 本身是系统组件、注入器要多一次进程操作，唯独 D3DX 这一层**游戏目录优先、且只被游戏用到**，最省事。

**请先备份你自己的 `d3dx9_40.dll`**（约 4.4 MB，安装脚本会自动改名成 `d3dx9_40_orig.dll` 并记录哈希）——
这是唯一的还原手段。

步骤：

1. 双击（或在 PowerShell 里跑）发布包里的 `tools\install.ps1`，指向游戏目录；
   它会校验原版 DLL 的 SHA-256 是否等于 `16FD909A…E216B`，再改名备份、复制补丁、建 `a11y\`。
2. 想要 NVDA 朗读，就把 32 位的 `nvdaControllerClient.dll` 放进 `a11y\`
   （**按许可证不随包分发**，见下面的「第三方组件」）；不放也能用，会自动回退争渡 / SAPI。
3. 启动游戏。安装记录写在 `a11y\install.json`（版本 / 时间 / 两个哈希 / 备份名）。

```cmd
rem 发布包解压后的目录里
powershell -ExecutionPolicy Bypass -File tools\install.ps1 -GameDir "<游戏目录>"
```

### 不用脚本，手动安装

发布包里的安装脚本只是把下面三步包起来，想自己看一遍就照这个做：

```cmd
rem 1) 备份原版（必须保留这个名字，代理 DLL 运行时会按它去找）
ren "<游戏目录>\d3dx9_40.dll" d3dx9_40_orig.dll
rem 2) 复制补丁
copy "<发布包解压目录>\d3dx9_40.dll" "<游戏目录>\d3dx9_40.dll"
rem 3) 建配置 / 日志目录（可选，补丁也会自己建）
mkdir "<游戏目录>\a11y"
```

补丁 DLL 的 SHA-256 会随版本变化，以发布包内 `VERSION.txt` 里写的为准。
**代理 DLL 必须和原版位于同一个目录**（它会从自己的目录加载 `d3dx9_40_orig.dll`）。

## 还原

把 `d3dx9_40_orig.dll` 改名回 `d3dx9_40.dll`，再删掉 `a11y\` 即可。
补丁不改动游戏本体逻辑，**不会留下任何残留**（存档在 `Saves\`、设置在 `Config.nkenv`，都是游戏自己写的）。
完整步骤见 `docs\安装说明.md`，或直接跑 `tools\uninstall.ps1`。

## 主要快捷键

> **本补丁不改变游戏本身的键盘行为。** 下面列游戏原生键、朗读侧热键与界面操作；
> 界面操作没有模式键，界面一出现就能用。

| 键 | 作用 | 归属 |
|---|---|---|
| `Enter` | 下一页 / 推进一句（游戏原生） | 游戏 |
| `Space` | 显示 / 隐藏对话框（游戏原生；**不是**翻页） | 游戏 |
| `Z` | 跳过（游戏原生，实测合成按键触发不了它） | 游戏 |
| 按住 `Ctrl` | 跳过（游戏原生，实测合成按键触发不了它） | 游戏 |
| `Esc` | 菜单 / 关闭菜单（游戏原生） | 游戏 |
| `F10` | 全屏 / 窗口（游戏原生） | 游戏 |
| 滚轮上 / 下 | 对话历史 / 下一页（游戏原生） | 游戏 |
| `Backspace` | 重读：念当前这一句（只念剧情与选项，见下） | 补丁 |
| `Ctrl+Backspace` | 重读上一句 | 补丁 |
| `Alt+Shift+F9` | 循环切换语音后端，念出结果；键位可在 `a11y\config.ini` 里改 | 补丁 |

**游戏原生占用键**：`Enter`、`Space`、`Z`、按住 `Ctrl`、`Esc`、`F10`、鼠标（移动 / 左键 / 滚轮）、
`F12`（Steam 截图）。补丁**不抢这些键**，也不把它们拿来当重读键。

**重读缓冲区只放剧情与选项**：菜单播报（"暂停菜单"、"选项，共 2 项"、设置项名称、存档位说明、
"已保存"这类系统提示）**不进缓冲区**，所以按 `Backspace` 永远念回剧情或选项，不会念出一串菜单名。

### 界面操作（没有模式键）

> 界面一出现，`↑`/`↓` 就能逐项浏览。

| 键 | 作用 |
|---|---|
| `↑` `↓` | 上一项 / 下一项，念出「名称。n / N」 |
| `←` `→` | 仅当选中的是滑条时生效：按轨道百分比调值并念结果 |
| `Enter` / `Space` | 激活当前控件（补丁代为点一次鼠标） |
| `Esc` | 返回上一层 / 交还游戏 |
| `Backspace` | 重读当前项 |

- **风险项要点两次**：标题的电源（退出游戏）、"回到标题"、语言切换这类会把进度弄丢 / 改变语言的项，
  第一次按 `Enter` 只播报"再按一次确认"，第二次才真的点。
- 游戏弹自己的确认框（「保存进度吗？」「读取进度吗？」「回到标题界面吗？」）时，
  补丁会把它识别成一个只有「是 / 否」两项的界面，`↑`/`↓` 选、`Enter` 定、`Esc` 等于"否"。
- 合成点击一次约 2.2 秒，界面正在切换时按下的键会被丢掉（日志里是 `menu: screen settling`）——
  这是有意的，避免连按把点击排满。

### 语音后端与切换快捷键

补丁启动时按 `NVDA` → `争渡读屏（ZDSR）` → `SAPI` 的顺序找后端，
找到一个就用；任一级失败都只降级，不报错、不中止。

- **NVDA**：用 32 位 `nvdaControllerClient.dll`。候选顺序：`a11y\config.ini` 同目录的
  `nvdaControllerClient.dll` / `nvdaControllerClient32.dll`、`<游戏目录>\a11y\`、`<游戏目录>\plugin\`、
  `<游戏目录>\`、环境变量 `A11Y_NVDA_CLIENT` 指定的路径。**不随包分发**（见「第三方组件」）。
- **争渡**：由 `ZDSRMain.exe` 真正出声（不是 `ZDSRMultiEngine.exe`）；可用性判据是
  `GetSpeakState()` ∈ {3 正在朗读, 4 空闲}，不是 `Speak()` 的返回值 —— 未授权时 `Speak()` 照样返回 0。
- **SAPI5**：中文念中文必须选中文语音（本机实测 Huihui，`Language=804`）；
  用英文语音念中文会 `S_OK` + 172 ms + **零音频**地静默失败，补丁会优先挑中文语音。
- `rate` / `volume` 只有 SAPI 能真正落地：NVDA 的客户端导出里没有这两个接口，
  争渡的 API 也没有，补丁不会假装调了。
- `Alt+Shift+F9` = 循环切换：**自动** → `NVDA` → `争渡` → `SAPI` → 回到**自动**。
  **当前不可用的后端会被跳过**，结果用**新后端**念出来；切换结果写回 `a11y\config.ini`，下次启动保持。

配置文件 `a11y\config.ini`（可选，UTF-8；补丁第一次运行会写一份带注释的模板）：

```ini
backend=nvda            # auto / nvda / zdsr / sapi，也可写「自动」「争渡」
re_read_key=Backspace   # 重读键；可写按键名或 0x08 这类虚拟键码
backend_key=Alt+Shift+F9
voice_window_ms=1200    # 判断"这一句有没有配音"的时间窗
speak_voiced_lines=0    # 1 = 有配音的台词也自动朗读（默认 0 = 静默）
min_stable_ms=260       # 文本多久不再增长才算一句念完
```

- 热键走低层键盘钩子，**只在本进程的游戏窗口是前台时**才响应；键位可以改、不用重新编译。
- `apply` 类（音量 / 语速）配置只对 SAPI 生效，其它后端会忽略并在日志里写一行原因。

## 已知问题 / 注意事项

- **本补丁不改变游戏本身的键盘行为**：`Enter` / `Space` / `Z` / 按住 `Ctrl` / `Esc` / `F10` /
  鼠标等游戏原生键照旧由游戏处理；补丁只新增朗读侧热键（`Backspace`、`Ctrl+Backspace`、
  `Alt+Shift+F9`）与无模式键的界面操作（`↑`/`↓`/`←`/`→`/`Enter`/`Esc`）。
- 界面键盘是**补丁补出来的**（C 型）：选中项只是朗读索引，不画 UI、不改游戏状态；
  完整逐界面清点与遗留缺陷见「交互形态判定摘要」与 `docs/交互形态判定.md`。
- **合成点击一次约 2.2 秒**：引擎只认"按住够久"的点击（120 ms / 700 ms 实测都被丢掉，
  2000 ms 稳定生效），所以界面操作有明显的等待感；连续操作时按键会排队。
- **存档落盘 / 读回没有自动化证据**：补丁能进入存档界面、能点存档格、能识别
  「保存进度吗？」并点"是"，但自动化测试里 `Saves\Save00.nkslot` 的时间戳没有变化，
  所以这一条在文档里按**未验证**写。手动用方向键选中存档格按回车应当可用，请以你的实机为准。
- 历史（backlog）界面只放行滚轮、**不朗读**；要看历史请用滚轮（游戏原生）。
- 滑条只播报离散档位（`←`/`→` 一次约 ±6%）；设置里少数项的"当前值"靠读游戏画的数字，
  个别项读不回来时只播报选项名。
- 剧情里的说话人：本作的中文版**没有独立的"说话人名字"绘制**，剧情框里只有台词本身，
  所以补丁念的是台词，不会念"露西："这样的前缀。**这一点与其它作品不同，是游戏本身如此。**
- 游戏原生"跳过"（`Z` / 按住 `Ctrl`）用合成按键**触发不了**，补丁也不假装能触发
  （日志会如实记 `key: vk=90 down`，但画面不动）；需要快进请用真键盘。
- 补丁的文字是**逐屏实机取证**来的，不是从游戏资源里解出来的（剧情文本一律不进仓库）。
  取证方法不给结论，只给做法，见 `docs\交互形态判定.md`。

## 构建

只需要一样外部东西：Visual Studio 的 32 位命令行环境。

```cmd
set VCVARS="D:\VS2022\VC\Auxiliary\Build\vcvars32.bat"
build\build.cmd
```

产物是 `build\out\d3dx9_40.dll`（代理 DLL，导出 336 个 D3DX 函数名，
其中 `D3DXCreateFontW` 等四个由补丁自己接管）。

**默认是发布构建**（release，不含任何开发通道）；`build\build.cmd dev` 是**开发构建**
（带 `log_draws` 详细绘制日志，**不要发给玩家**）。
发布构建里开发通道是**编译期不存在**的。

构建脚本**强制 32 位**：先用 `vcvars32.bat` 设下的 `VSCMD_ARG_TGT_ARCH` 判一次，
链接时再带 `/MACHINE:X86`。用 64 位环境跑会**直接失败**，
而不是像以前那样报 `BUILD_OK` 却产出一个装不上的 x64 DLL。

### 构建是可复现的

用仓库自带的源码、按上面的脚本构建（**0.1.0.1 未做逐字节复现对比**，只核对了导出表）：
`tools\check-staged.ps1` 会机械断言"新旧 DLL 的导出名集合与原件完全一致"（336 个，无一缺失、无一多余、
无修饰名），这一条每版都跑。

| 指标 | 结果 |
|---|---|
| 导出名集合 | **逐名一致（336 / 336，missing=[] extra=[] decorated=[]）** |
| 文件大小 | 随版本变化（0.1.0.1 约 262 KB） |
| PE 架构 | **i386（0x014c）**，32 位 |

（"可复现"目前只覆盖到导出表与架构；逐字节对比还**没做**，不写没做过的结论。）

### 模组做了什么

1. **进程内代理 DLL，不是伴随程序。** 最早考虑过宿主进程 + 管道 + 伴随窗口：
   要跨进程抢焦点，读屏软件念的是伴随窗口而不是游戏，操作永远和游戏对不上。
   改成游戏自己加载的 `d3dx9_40.dll` 代理后，文字从游戏进程内直接交给读屏 DLL，
   没有第二份焦点、第二个窗口。
2. **语音后端链**：`NVDA Controller` → 争渡读屏 `ZDSRAPI` → `SAPI5`（纯 COM 调用）。
   任一级失败都只降级，绝不把异常抛回游戏主循环。
   `Alt+Shift+F9` 可在**当前可用**的后端之间循环切换，选择记在 `a11y\config.ini`。
   NVDA / Tolk 走**直投**（投递成功即算念完，下一句立刻取；`Speech_SpeakImmediate` 先取消再投 = 真打断）。
3. **文本发现**：替换 `D3DXCreateFontW`，拿到每个新字体的 `ID3DXFont` 对象，把它的虚表复制一份、
   把槽 15（`DrawTextW`）换成自己的函数，其余槽原样转发。
   写盘日志只记"文本长度 + 前若干字"用于分类，剧情原文只有玩家自己的机器上有。
4. **分类不靠猜坐标**：`fmt` 位（`0x410` 剧情框、`0x100` 界面点框、`0x400` 模态框）+ 框宽 + 字号
   + "是否成对出现"决定一份绘制是剧情、选项、模态框还是页码；详见 `docs\交互形态判定.md`。
5. **配音判据**：`nekoHWMusic` 静态虚表（`Engine.dll+0x1FA004`）slot 7 = 播放，
   看"台词行开始 900 ms 内是否出现一次孤立播放，且 `dur_ms>=1500`、`size>=15000`"，
   预载爆发（同一瞬间 8 条）排除；带配音则不自动念，只进重读缓冲区。

### 几条踩过的坑（改之前请先读）

- **引擎对"点一下"的定义是按住 2 秒**：投递 `WM_LBUTTONDOWN` + 120 ms 后 `WM_LBUTTONUP`，
  窗口过程收到了、游戏毫无反应；700 ms 也不行；2000 ms 稳定生效。别把它"优化"成短按。
- **标题按钮用的是真实光标位置**（`GetCursorPos`），只投 `WM_MOUSEMOVE` 没用 ——
  必须同时 `SetCursorPos`。游戏内菜单不需要真实光标，所以只有标题这一层会踩。
- **`Engine.dll` 根本不通过自己的 IAT 调 `GetAsyncKeyState`**：我们把它 `patch` 成假按键、
  日志里 `while faked` 计数却是 0 —— 靠假按键骗不过它，最后是"按住时长"救了场。
- **不要修补 audiere 流的实例虚表**：给 `OutputStream` / `SoundEffect` 的实例复制虚表并改槽，
  实测让游戏 `c0000005` 崩溃（模块 unknown）；静态虚表上打一个指针是安全的（`nekoHWMusic` slot 7）。
- **`Engine.dll` 的 audiere 导入名是 stdcall 修饰名**：`_AdrOpenDevice@8`、`_AdrOpenSound@12`……
  按裸名 `strcmp` 永远匹配不到，IAT 补丁看起来"装上了"其实一条没中。
- **剧情框"框宽"可能是负数**：读档之后引擎给 `DrawTextW` 的矩形 `right` 是负的（实测 `-82`），
  用"框宽 < 600 → 不是剧情"的判据会把读档后所有台词全丢掉。负宽度要当剧情。
- **`fmt & 0x100` 的"点框"是界面文字**：选项、页码、存档位标签全是 1×1 点框，
  和剧情框的 990 宽完全不是一回事；早期把它当噪声过滤，结果选项永远识别不到。
- **一个进程会有两个"游戏"**：`Lucy.exe` 是个加壳启动器，启动后走 SteamAPI 重开一份真进程。
  补丁必须在**等不到 `NekoEngine` 窗口时什么也不做**，否则会在启动器里白起一遍语音后端。
- **不要用命名管道 / 匿名管道抓子进程输出**：本机沙箱模式下会 `EPERM`；
  分析的辅助进程一律写文件、再读文件。

## 如何复现分析

补丁的每一条结论都来自两类证据之一：**运行时探针**，或**对游戏自己绘制出口的读取**。

1. **运行时探针**：补丁里有一段开发用的探针模式 —— 在代理 DLL 同目录放一个
   `lucy_probe.mode` 文件（首字符 `s`/`a`/`r`/`t`），DllMain 就会挂上不同深度的钩子，
   把 `ID3DXFont` 虚表各槽的调用、实参、返回地址、绘制文本写进 `lucy_probe_<pid>.log`。
   本仓库里几乎所有"游戏里到底发生了什么"的结论（槽位语义、`fmt` 位、框宽、模态框签名）
   都出自它。发布构建里这段探针**在编译期就不存在**。
2. **游戏自己的文本出口**：能问游戏要的就问游戏要 ——
   `Engine.dll` 的静态虚表（`nekoHWMusic` 的 play/stop 是什么 RVA）、
   `Localizations.xml` 里的系统提示串、`Game.nkpublished` 里的产品信息。
   这样拿到的永远是正确的用词，也不用自己造。

```powershell
# 装好 VS 的 32 位环境后
build\build.cmd
```

**界面标签的取证**：游戏的界面文案是**按语言预渲染成图片**的，
没有可直接读的文本表。所以界面上的每一项都是**切到目标界面、逐屏截图、对着控件坐标逐项抄**出来的。

## 内容边界

本仓库严格遵守一条线：**任何会影响开发商与发行商利益的内容都不入库**。

### 做了什么、没做什么

说清楚，免得读者误会：

- **做了**：在正版游戏上跑运行时探针，观察游戏自己调用 D3DX 时传了什么；
  读游戏**本来就以明文存在**的配置与发行描述（`Localizations.xml`、`Game.nkpublished`）；
  逐屏截图，把界面上的文字抄成标签。
- **没做**：没有破解 `nkpack` 归档 —— 本作的脚本归档是加密 / 自定义压缩的，
